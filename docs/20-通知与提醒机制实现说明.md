# CampusPilot 通知与提醒机制实现说明

## 一、概述

Phase 3 新增通知中心与定时提醒：任务由 Workflow 创建后即时异步通知（TASK）；
临近截止自动提醒（REMINDER），并保证提醒幂等（每任务仅发送一次）。

## 二、表结构（notifications）

| 字段 | 说明 |
|------|------|
| id | 主键（自增） |
| user_id | 通知归属用户 |
| student_id | 所属学生（可空，兼容学生视角） |
| type | 类型：SYSTEM / TASK / REMINDER / INFO |
| title / content | 标题与内容 |
| related_id | 关联业务对象（如任务ID） |
| is_read | 是否已读 |
| created_at | 创建时间 |

## 三、服务与接口

| 组件 | 说明 |
|------|------|
| `NotificationEntity/Mapper` | MyBatis-Plus 访问层 |
| `NotificationService(Impl)` | 获取当前用户通知 / unread-count / 标记已读 / 已读全部 / 发送 |
| `NotificationVO` | 视图对象 |
| `NotificationController` | REST 接口（见下） |

接口（均需 JWT）：

| 接口 | 说明 |
|------|------|
| `GET /api/notifications` | 当前用户通知列表 |
| `GET /api/notifications/unread-count` | 未读数 `{count}` |
| `PUT /api/notifications/{id}/read` | 标记单条已读 |
| `PUT /api/notifications/read-all` | 全部已读 |

## 四、任务创建联动

`TaskCreationWorkflow` 在 `create_todo` 成功后调用 `notificationService.send(...)`：

```
userId=当前用户, type=TASK, title=任务已创建
content=任务「X」已创建，请按时完成（截止 2026-09-30 23:59:59）
related_id=taskId
```

该步骤在 Trace 中以 `NOTIFY` 步骤呈现（含 notificationId）。通知为真实 DB 写入。

## 五、提醒调度（ReminderScheduler）

- `ReminderService.processDueReminders()` 每分钟扫描（`@Scheduled(cron = "0 * * * * *")`）。
- 规则：任务 `status=PENDING` 且 `due_at <= now` 且 `reminder_sent=false` 且截止+1 天内尚未完成任务。
- 对命中任务发送 `REMINDER` 通知（related_id=任务ID），并置 `reminder_sent=true`（幂等）。
- 调度器由 `@EnableScheduling` 启用（已确认在配置类声明）。

## 六、验证

2026-09-10 HTTP 回归：任务创建后通知列表出现 TASK 类型；`unread-count` 正常返回；
通知接口均通过（见 Phase3-自检报告）。

## 七、边界

- 定时提醒触发时间依赖测试数据 due_at；当前 DEMO 任务截止时间为未来日期（2026-09-30），
  验证时可将某任务 due_at 置近过期观察 REMINDER 通知产生。
