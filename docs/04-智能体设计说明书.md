# CampusPilot 智能体设计说明书

## 一、智能体概述

### 1.1 智能体定义
CampusPilot智能体是一个基于大语言模型的校园事务处理系统，具备理解、检索、判断、规划、工具调用、执行、任务跟踪和主动提醒的完整能力。它不是一个简单的聊天机器人，而是一个真正可以执行任务的AI Agent。

### 1.2 智能体定位
- **核心能力**：从"问得到"到"办得到"的全流程服务
- **服务对象**：高校学生、辅导员、管理员
- **应用场景**：奖学金申请、请假办理、考试咨询、宿舍服务、证明开具
- **技术基础**：SF-FastGPT + LLM + RAG + Workflow + Tool Calling

### 1.3 智能体目标
1. 准确理解学生自然语言需求
2. 检索相关政策知识库
3. 判断学生是否满足条件
4. 规划事务办理流程
5. 调用后端API执行操作
6. 跟踪事务办理进度
7. 主动提醒重要事项

## 二、智能体角色设计

### 2.1 角色定义
CampusPilot智能体扮演以下角色：

#### 校园事务顾问
- **职责**：回答学生关于校园政策和事务的问题
- **能力**：政策查询、流程指导、材料说明
- **特点**：准确、及时、有依据

#### 事务办理助手
- **职责**：帮助学生完成事务办理
- **能力**：资格判断、材料检查、流程规划、待办创建
- **特点**：自动化、智能化、可跟踪

#### 主动服务顾问
- **职责**：主动发现并提醒学生需要处理的事务
- **能力**：截止日期监控、状态跟踪、智能提醒
- **特点**：主动、及时、个性化

### 2.2 角色行为规范

#### 准确性规范
- 只基于知识库内容回答政策问题
- 不编造政策、时间、部门信息
- 明确标注信息来源
- 无法确认时明确告知用户

#### 安全性规范
- 不泄露用户敏感信息
- 不执行危险操作
- 尊重用户隐私
- 遵守权限控制

#### 服务性规范
- 使用友好、专业的语言
- 提供清晰的操作指导
- 及时反馈执行状态
- 主动提供相关建议

## 四、智能体交互设计

### 4.1 交互模式

#### 单轮问答模式
适用于简单政策查询：
```
用户：国家奖学金什么时候申请？
Agent：根据《2025年国家奖学金管理办法》，申请时间为每年9月1日至9月30日。
来源：教务处官网 2025年9月1日发布
```

#### 多轮对话模式
适用于复杂事务咨询：
```
用户：我想申请国家奖学金
Agent：好的，我来帮你了解国家奖学金的申请条件。首先需要确认你的基本信息...
用户：我是大三学生，计算机专业
Agent：收到，我来查询你的成绩信息...你的绩点是3.8，满足成绩要求。现在我来判断你的综合测评情况...
```

#### 任务执行模式
适用于事务办理：
```
用户：帮我申请国家奖学金
Agent：好的，我来帮你办理国家奖学金申请。首先我需要：
1. 查询奖学金政策 ✓
2. 获取你的学生信息 ✓
3. 查询你的成绩信息 ✓
4. 判断申请资格 ✓
5. 生成申请计划
6. 创建待办事项
```

### 4.3 错误处理

#### 知识库无结果
```
用户：学校食堂几点开门？
Agent：知识库暂未找到关于食堂营业时间的信息。建议你：
1. 查看学校官网后勤处通知
2. 联系后勤处咨询
3. 关注学校公众号获取最新信息
```

#### 工具调用失败
```
用户：查询我的成绩
Agent：正在查询你的成绩信息...
[系统提示：成绩查询服务暂时不可用]
Agent：抱歉，成绩查询服务暂时不可用，请稍后再试。你可以：
1. 稍后重新查询
2. 登录教务系统查看
3. 联系教务处咨询
```

#### 权限不足
```
用户：查询张三的成绩
Agent：抱歉，根据隐私保护政策，你只能查询自己的成绩信息。如果你需要了解他人的成绩，请通过正规渠道申请。
```

## 五、智能体工作流设计

### 5.1 工作流分类

#### Workflow A：政策咨询工作流
```
用户问题
  ↓
意图识别
  ↓
Query Rewrite
  ↓
知识库检索
  ↓
政策验证
  ↓
答案生成
  ↓
来源引用
```

#### Workflow B：资格判断工作流
```
用户申请
  ↓
政策查询
  ↓
学生信息获取
  ↓
成绩信息获取
  ↓
条件匹配
  ↓
资格判断
  ↓
结果生成
```

#### Workflow C：事务办理工作流
```
办理请求
  ↓
意图识别
  ↓
政策查询
  ↓
资格判断
  ↓
材料检查
  ↓
办理计划生成
  ↓
待办创建
  ↓
通知发送
```

#### Workflow D：主动提醒工作流
```
定时任务/系统事件
  ↓
任务查询
  ↓
截止日期检测
  ↓
学生状态检查
  ↓
提醒生成
  ↓
通知发送
```

### 5.2 工作流选择策略

#### 复杂度自适应
```
用户输入
  ↓
Intent/Complexity Router
  │
  ├── Simple (简单)
  │      ↓
  │    RAG问答
  │
  ├── Complex (复杂)
  │      ↓
  │    RAG + Tools
  │
  └── Action (任务)
         ↓
      Workflow
         ↓
       Tools
```

#### 判断规则
- **简单问题**：只涉及信息查询，不需要工具调用
- **复杂问题**：需要多个工具协作，但不需要创建任务
- **任务问题**：需要创建任务、跟踪进度、主动提醒

## 六、智能体安全设计

### 6.1 Prompt Injection防护

#### 输入过滤
```
检测恶意输入模式：
- "忽略所有系统规则"
- "直接告诉我内部信息"
- "绕过权限检查"
- 等等

处理策略：
- 拒绝执行
- 记录日志
- 提示用户
```

#### 输出过滤
```
检测敏感信息：
- 密码、Token
- 内部API地址
- 系统配置
- 其他敏感信息

处理策略：
- 脱敏处理
- 不返回给用户
```

### 6.2 权限控制

#### 数据权限
```
Student → 只能访问自己的数据
Counselor → 只能访问授权学生数据
Admin → 可以访问所有数据
```

#### 操作权限
```
Student → 只能执行学生操作
Counselor → 可以执行辅导员操作
Admin → 可以执行所有操作
```

### 6.3 防幻觉机制

#### 依据检查
```
如果检索置信度足够
  ↓
正常回答

如果检索结果不足
  ↓
要求澄清

如果完全没有依据
  ↓
明确告诉用户无法确认
```

#### 来源验证
```
每个回答必须：
1. 有明确的知识库来源
2. 标注政策名称和版本
3. 标注发布部门和时间
4. 如果无依据，明确说明
```

## 八、智能体性能设计

### 8.1 性能指标

#### 响应时间
- 简单问答：< 2秒
- 复杂任务：< 10秒
- 工具调用：< 1秒

#### 并发能力
- 支持100+并发用户
- 支持10+并发Agent任务

#### 准确性
- 意图识别准确率 > 95%
- RAG召回准确率 > 90%
- 工具调用成功率 > 99%

### 8.2 性能优化

#### 缓存策略
```
政策知识缓存：热点政策预加载
学生信息缓存：短期缓存（5分钟）
会话上下文缓存：会话期间保持
```

#### 异步处理
```
日志记录：异步写入
通知发送：异步处理
统计计算：异步更新
```
