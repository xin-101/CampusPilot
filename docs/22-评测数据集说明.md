# CampusPilot 评测数据集说明

## 一、概述

阶段 3 在 `evaluation/` 目录建立离线评测数据集，对 Agent 对话服务
（`POST /api/agent/chat`）进行可量化评测，覆盖七类能力：政策问答、资格判断、
任务办理、通知联动、安全拦截、执行轨迹、通用回退。

## 二、数据文件

| 文件 | 说明 |
|------|------|
| `evaluation/README.md` | 指标定义与评测流程 |
| `evaluation/cases.json` | 32 条用例（E001–E032） |

分布：POLICY_QA×8、ELIGIBILITY×6、TASK_CREATION×4、NOTIFICATION×2、
SECURITY×6、TRACE×4、FALLBACK×2。

## 三、六项指标（M1–M6）

| 指标 | 名称 | 度量 |
|------|------|------|
| M1 | answerAccuracy 答案事实准确性 | 命中要点/总要点 (0-100) |
| M2 | completeness 完整性 | 政策信息/依据/有效期/免责声明覆盖 (0-100) |
| M3 | citationHit RAG引用命中 | citations 非空且相关 (0-100) |
| M4 | answerSafety 安全合规 | 恶意/越权拦截与合规 (0/100) |
| M5 | workflowCorrectness 工作流正确性 | workflowId/步骤/工具/决策符合预期 (0-100) |
| M6 | stability 稳定性 | 同输入重复执行一致性 (0-100) |

## 四、状态语义

- `status: "NOT_RUN"`：需要真实 LLM（SF-FastGPT）生成答案后方可评测 M1/M2/M6，
  当前环境未就绪，标注待评（不伪造分数）。
- `status: "PASSED_3_9"`：确定性执行路径（规则引擎/安全守卫/工作流路由/通知）已由
  `test_phase3.mjs`（2026-09-10，12/12 PASS）验证通过的部分。

## 五、评测流程

1. 启动后端（dev profile，`database/init.sql` 全量数据）。
2. `POST /api/auth/login` 获取 JWT。
3. 携带 JWT 调 `POST /api/agent/chat`，断言 `trace.workflowId`、steps、toolCalls、decisions。
4. 回填 results 并按 M1–M6 打分。
5. FastGPT 环境就绪后，补齐 NOT_RUN 用例的 M1/M2/M6。
