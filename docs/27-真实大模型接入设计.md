# 27-真实大模型接入设计（Phase 6）

## 1. 架构概述

### 1.1 从 Mock 到 LLM 的升级路径

```
Phase 5 (Mock)                      Phase 6 (LLM)
┌─────────────┐                     ┌─────────────────┐
│ MockAgent   │                     │ RealLLMAgent    │
│ Provider    │                     │ Provider        │
│ (keyword)   │                     │ (LLM-driven)    │
└──────┬──────┘                     └────────┬────────┘
       │                                     │
       ▼                                     ▼
┌─────────────┐                     ┌─────────────────┐
│ Workflow    │                     │ LLMGateway      │
│ Engine      │◄────────────────────│ (OpenAI-compat) │
│ (deterministic)                   └─────────────────┘
└─────────────┘
```

### 1.2 设计原则

**CampusPilot 本身就是 Agent**。不引入 Spring AI / LangChain4j / 任何外部 Agent 框架。

LLM 在架构中的定位：
- ✅ **自然语言理解**：意图识别、实体抽取
- ✅ **复杂度分析**：判断是否需要规则引擎
- ✅ **自然语言生成**：解释工作流结果
- ❌ **不做**：资格判断、规则评估、安全检查、任务创建、权限验证

### 2.4 AgentServiceImpl (Runtime Provider Selection)

```java
@Service
public class AgentServiceImpl implements AgentService {
    private final MockAgentProvider mockProvider;
    private final Optional<RealLLMAgentProvider> llmProvider;

    private AgentProvider selectProvider() {
        if (llmProperties.isReallyConfigured() && llmProvider.isPresent()) {
            return llmProvider.get();  // Real LLM
        }
        return mockProvider;  // Fallback
    }
}
```

## 3. 数据流

### 3.1 LLM 模式完整流程

```
User Message
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ Phase 1: Security Guard (deterministic, ~20ms)              │
│ - Input inspection, injection detection                      │
│ - Block prompt leak, admin impersonation, tool injection    │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ Phase 2: LLM Intent Classification (~1-3s)                   │
│ - System prompt + user message → LLM                        │
│ - Parse JSON: {intent, complexity}                          │
│ - Validate against whitelist                                 │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ Phase 3: WorkflowEngine (deterministic, ~50-200ms)          │
│ - Route to policy_consultation / eligibility_check / etc.   │
│ - RAG retrieval, rule evaluation, tool calls                 │
│ - Returns WorkflowResult with data + citations              │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ Phase 4: LLM Explain (~1-2s)                                │
│ - Workflow result → LLM                                     │
│ - Generate natural language response                        │
│ - Include citations, eligibility status, etc.               │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
AgentResponse (with ExecutionTrace)
```

### 3.2 错误处理策略

| 错误场景 | 处理方式 | 用户看到 |
|---------|---------|---------|
| LLM HTTP 401/403 | 返回错误信息 | "AI 服务暂时不可用" |
| LLM HTTP 429 | 返回错误信息 | "AI 服务暂时不可用" |
| LLM HTTP 500 | 返回错误信息 | "AI 服务暂时不可用" |
| LLM 超时 | 返回错误信息 | "AI 服务暂时不可用" |
| LLM 连接拒绝 | 返回错误信息 | "AI 服务暂时不可用" |
| LLM 返回非法 JSON | 使用关键词 fallback | 正常响应 |
| LLM 未配置 | 使用 MockAgentProvider | 正常响应 (Mock) |

**永不静默切换**：`LLM_FALLBACK_TO_MOCK=false`（默认）。LLM 失败就报错，不偷偷用 Mock。

## 4. 安全设计

### 4.1 API Key 安全

```
❌ 绝不：写入 Git、源代码、日志、测试报告
✅ 仅通过：环境变量 LLM_API_KEY 注入
✅ Docker：docker-compose.yml 中 ${LLM_API_KEY:-}
```

### 4.2 LLM 绕不过的防线

LLM 只负责自然语言处理，以下全部由确定性代码执行：
- Security Guard（6 类恶意输入拦截）
- Rule Engine（资格判断公式计算）
- Tool Registry（权限检查）
- Task Ownership（任务归属验证）

### 4.3 LLM 安全边界

```
User Input
    │
    ▼
Security Guard ←── 确定性，不依赖 LLM
    │
    ▼
LLM Intent ←── LLM 只返回意图，不执行任何操作
    │
    ▼
WorkflowEngine ←── 确定性，不依赖 LLM
    │
    ▼
LLM Explain ←── LLM 只解释结果，不修改数据
```

## 5. 配置指南

### 5.1 环境变量

```bash
# 启用 LLM 模式
LLM_ENABLED=true

# OpenAI-compatible API 地址
LLM_BASE_URL=https://api.openai.com/v1

# API Key（仅通过环境变量注入）
LLM_API_KEY=sk-xxxx

# 模型名称
LLM_MODEL=gpt-4o

# 可选配置
LLM_TEMPERATURE=0.2
LLM_TIMEOUT_MS=30000
LLM_FALLBACK_TO_MOCK=false
```

### 5.2 Docker 部署

```yaml
# docker-compose.yml
environment:
  - LLM_ENABLED=${LLM_ENABLED:-false}
  - LLM_BASE_URL=${LLM_BASE_URL:-}
  - LLM_API_KEY=${LLM_API_KEY:-}
  - LLM_MODEL=${LLM_MODEL:-gpt-4o}
```

### 5.3 Provider 切换

```
AGENT_PROVIDER=mock    → MockAgentProvider (keyword-based)
AGENT_PROVIDER=llm     → RealLLMAgentProvider (LLM-driven)
AGENT_PROVIDER=fastgpt → FastGPTProvider (optional adapter)
```

运行时自动选择：
- LLM 已配置 + enabled → RealLLMAgentProvider
- 否则 → MockAgentProvider

## 7. 创新点

1. **LLM 作为大脑，确定性代码作为骨架**：不依赖外部 Agent 框架，CampusPilot 本身就是 Agent
2. **运行时 Provider 切换**：无需重启，配置即切换
3. **LLM 不绕过安全防线**：Security Guard → LLM → WorkflowEngine，层层防护
4. **OpenAI 兼容接口**：支持 GPT/DeepSeek/Qwen，一处配置，随时切换
5. **优雅降级**：LLM 不可用时返回友好错误，不静默切换 Mock
6. **ExecutionTrace 记录真实 LLM 推理**：每一步都有迹可循
