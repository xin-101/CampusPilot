# CampusPilot 资格规则引擎实现说明

## 一、概述

资格判断采用**确定性规则引擎**而非 LLM 自由判断：LLM 仅负责解释，最终结论由规则引擎依据
学生画像与启用规则计算得出，保证可复现、可审计、可追溯。规则数据与政策版本均来自 MySQL，
与 RAG 命中的"有效期政策"一致。

## 二、核心组件

| 类型 | 说明 |
|------|------|
| `EligibilityRuleEngine` | 规则执行器（确定性匹配 + 状态判定 + 证据/解释生成） |
| `EligibilityRuleService` | 规则加载：按分类（category）或按来源政策（source_policy_id） |
| `EligibilityCheckService` | 编排：政策定位(RAG) → 学生画像 → 规则引擎 |
| `StudentProfileService` | 由 SecurityContext 构建当前登录学生画像（DEMO：年级按入学年份+Now 推算） |
| `EligibilityResult` | 结果：eligible / status / score / matchedRules / failedRules / explanation / evidence / demo |

## 三、状态判定规则

按优先级：

| 状态 | 条件 |
|------|------|
| `NOT_ELIGIBLE` | 存在必选规则未通过（字段值真实但不满足） |
| `INSUFFICIENT_DATA` | 存在必选规则因字段缺失无法评估 |
| `CONDITIONALLY_ELIGIBLE` | 必选全部通过，存在可选规则未通过 |
| `ELIGIBLE` | 全部规则通过 |

- 支持运算符：`EQ` / `GT` / `GTE` / `LT` / `LTE` / `IN` / `CONTAINS`。
- 综合评分 = 通过规则权重 / 总权重 × 100。

## 四、规则范围（关键设计）

规则既可以按 `category` 聚合，也可以按 `source_policy_id` 精确归属。**优先按来源政策取规则**，
未命中时按分类兜底。这样避免"励志奖学金"的经济困难规则误作用于"国家奖学金"判断。

示例（`eligibility_rules`，均 `is_demo=1`）：

| rule_id | source_policy_id | 字段 | 运算符 | 期望值 |
|---------|------------------|------|--------|--------|
| DEMO_RULE_SCH_GRADE | 1（国家奖学金） | GRADE | IN | 3,4 |
| DEMO_RULE_SCH_GPA | 1 | GPA | GTE | 3.5 |
| DEMO_RULE_SCH_RANK | 1 | RANK | LTE | 10 |
| DEMO_RULE_AID_GRADE | 2（励志奖学金） | GRADE | IN | 2,3,4 |
| DEMO_RULE_AID_HARDSHIP | 2 | HARDSHIP | EQ | true |
| DEMO_RULE_AID_STATUS | 3（助学金） | STATUS | EQ | ENROLLED |
| DEMO_RULE_AID_HARDSHIP2 | 3 | HARDSHIP | EQ | true |

验证结果（2026-09-10 HTTP 回归）：张三(绩点3.8/排名前10/年级4) 判断国家奖学金 → **ELIGIBLE**。

## 五、接口

- `POST /api/eligibility/check`：body `{policy?, category?, policyId?}`（三者至少其一）。返回 `EligibilityResult`。
- Agent 链路：`ELIGIBILITY_CHECK` 意图 → `EligibilityCheckWorkflow` → `check_eligibility` 工具
  → `EligibilityCheckService` → 规则引擎。

## 六、DEMO 边界

- 规则/画像均为演示数据（`is_demo=1`，页面与回答含免责声明），不代表真实校规审核结果。
- 画像字段缺失时按 `INSUFFICIENT_DATA` 处理，保证"不臆断"。
